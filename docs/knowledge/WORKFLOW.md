# 知识管理工作流

> 本文档定义了 Agent 如何收集、构建、更新和调用训练知识库。
> 同时作为知识库维护者的操作手册。

---

## 一、整体流程

```
收集 → 归类 → 精炼 → 索引 → 调用
  │       │       │       │       │
  ▼       ▼       ▼       ▼       ▼
 识别    分类    提取    更新    按需
 来源    主题    核心    _index   加载
 拉取    拆分    标注    引用
 内容            来源
```

---

## 二、具体步骤

### Phase A: 收集

**触发条件**：用户确认某来源可信（博主、书籍、论文）

**执行步骤**：
1. 搜索该来源的代表性内容（B站视频、文章、书籍章节）
2. 提取关键论点和原则
3. 记录来源元数据：
   - 来源名 / 作者
   - 平台 / 链接
   - 内容领域（训练/营养/恢复/动作技术）
   - 可信等级（可信 / 参考 / 待验证）

**输出**：原始笔记，存入 `_inbox/` 目录

### Phase B: 归类

1. 判断内容属于哪个主题域
2. 如果现有文件能容纳 → 追加
3. 如果需要新文件 → 创建（按 `NN-topic.md` 命名）
4. 如果与现有观点冲突 → 保留双方观点，标注分歧

### Phase C: 精炼

每条知识条目遵循标准格式：

```markdown
### 主题标题

- 核心观点（一句话）
- 具体内容（1-3 行）
- 适用范围 / 例外情况
- [来源: 作者-视频/文章名]
```

原则：
- 每条不超过 5 行
- 保留来源可追溯
- 只收录已验证或来源明确的内容

### Phase D: 索引

更新 `_index.md` 中的目录，确保 agent 通过读 `_index.md` 就能判断需要加载哪些文件。

### Phase E: 调用

Agent 使用知识库的流程：

1. 加载 train skill → 看到 `@knowledge/_index.md` 引用
2. 读 `_index.md`，判断当前问题需要哪部分
3. 用 Read 工具只加载相关文件
4. 结合 `profile.md` 和数据库数据输出定制建议

## 三、文件结构

```
.agents/knowledge/
├── WORKFLOW.md          ← 本文档
├── _index.md            ← 目录 / 速查
├── sources.md           ← 来源清单（链接、可信等级）
│
├── 01-principles.md     ← 训练核心原则
├── 02-programming.md    ← 计划设计（分化、频率、容量）
├── 03-exercises.md      ← 动作技术与替代
├── 04-recovery.md       ← 恢复、伤病预防与处理
├── 05-nutrition.md      ← 营养与补剂
│
├── _inbox/              ← 原始收集暂存区
│   └── YYYY-MM-DD-source-name.md
└── _archive/            ← 已替换的旧版本
```

## 四、来源可信等级

| 等级 | 含义 | 示例 |
|------|------|------|
| ⭐⭐⭐ | 实战验证 + 学术背景 | BrucePhD（运动学博士） |
| ⭐⭐ | 长期实战验证 | 自强不息归来（自然训练多年） |

| 📌 | 用户个人偏好 | 你的 profile.md 中的记录 |

## 五、更新策略

- **增量更新**：新来源不重写，只追加
- **分歧处理**：对同一问题不同来源有分歧时，保留双方观点并标注
- **移除标准**：来源被证伪或用户明确不再信任时，移至 `_archive/`
